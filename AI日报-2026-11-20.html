谷歌在 Gemini API 上线 Tool Retrieval 预览：先只暴露工具名与描述，需要时再加载完整参数 schema

谷歌 11 月 19 日官方博客宣布，Tool Retrieval 已在 Gemini Interactions API 中进入预览。当智能体连接几十甚至上百个工具时，每次请求都带上完整参数 schema 会推高输入 token、增加延迟，并可能降低选工具的准确率。新机制让开发者把 `tool_search` 加进请求，并对希望暂缓加载的工具设置 `defer_loading: true`：模型仍能看到这些工具的名称和描述，但参数 schema 先不进上下文；需要时由接口在同一次请求里加载完整 schema 再发出 function call。远程 MCP 服务器也可设置 defer_loading，从而不必逐一声明该服务器上的工具。若团队自建工具注册表或权限过滤，还可以把 `tool_search` 设为客户端执行。官方称这项能力没有单独收费，按所调用模型的标准输入输出计价；适用于 Gemini 3.6 及之后的模型，包括所有 Gemini 4。博客示例使用的是 gemini-4-hydrogen。

GateWatch：用布尔电路做低开销的大模型行为监控

GateWatch: Low-Overhead LLM Monitoring with Boolean Circuits · Firas Spanioli, Yaniv David

激活探针可以监测大模型是否做出不安全或非预期的动作，但现有方法往往要在准确率、可解释性和开销之间取舍：直接打在原始激活上的探针不好解释，基于稀疏自编码器（SAE）的探针又常常依赖加法分类器和庞大的编码器。Firas Spanioli 与 Yaniv David 提出 GateWatch，把整条判定规则写成对少量二值化 SAE 特征的显式布尔逻辑，并在给定门数预算下尝试了三种构图方法。在 Gemma-2-9B 的 24 项任务上，GateWatch 平均每枚探针只用 3.8 个 SAE 特征和 3.5 个逻辑门，测试准确率 80.49%，仅比使用全部 1.6 万个特征的 SAE 探针低 1.17 个百分点，并在 10 项任务上持平或更好；探针内存可降约 99.98%。部署在 vLLM 中时，1000 个并发的多层、多 token 分类器仍能保留基线吞吐的 97–98%，以及 99.8% 的 KV cache 容量。

不要把潜在推理跑满预定步数：多跑反而可能把正确答案冲淡

Rethinking Fixed-Horizon Latent Reasoning · Tianxiang Chen, Jingyuan Zhou, Weiming Yang, Kaidi Yang

现有潜在推理器通常在推理时跑满预先设定的潜在步数，直觉上「想得更久」应当更好。Tianxiang Chen、Jingyuan Zhou、Weiming Yang 与 Kaidi Yang 发现，把潜在思维链拉到满预算，有时反而会损害推理表现：前期计算更像在形成前沿推理状态，后期则主要在重排已有候选，并可能削弱对正确候选的支持。他们用「已实现的建设性进展」和「剩余进展」来刻画收益，并给出一种在推理时估计剩余进展、从而自适应调整潜在步数的轻量方法。在多种潜在思维链推理器和若干算术基准上，该方法最多把推理准确率提高 7.2 个百分点，同时最多减少 29.0% 的潜在计算，且不必重新训练模型。

https://arxiv.org/abs/2611.24001

SCAFFOLD：技能昨天跑通了，不代表今天还有理由再用

SCAFFOLD: Toward Warrant-Preserving Evidence Transport for Reusable LLM-Agent Skills · Nami Cho, Shailja Gupta

Nami Cho 与 Shailja Gupta 提出，智能体技能「今天还能执行」和「今天仍有理由复用」不是一回事：测试可能只覆盖可观察的契约条款，结果判定器可能缺位，评估还可能继承同一份错误规格，权限和依赖也会在验证与调用之间发生变化。他们把前瞻信任的单位定义为有条件的「有担保复用主张」（Warranted Reuse Claim），并讨论在情境变化后，哪些历史证据仍然可被采纳（Warrant-Preserving Evidence Transport）。文章区分了证据可采纳性与所支持安全或有效性主张是否为真，给出有条件的保持结果及其边界，并说明溯源依赖与会作废策略的变化如何改变授权。作者明确说，这是形式化的问题陈述、可检验的设计义务和报告协议，而不是已实现的验证器，也不声称在实验上优于现有基线，或证明了普遍的智能体安全。
