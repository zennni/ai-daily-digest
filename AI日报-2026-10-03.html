了解这个记忆库：智能体能读取之前，后端必须先写下什么（Knowing the Store: What a Memory Backend Must Write Down Before an Agent Can Read It）arXiv 2610.04794v1

带长期记忆的智能体可能会依据一条本不该再使用的记录作答，比如用户后来已取消的计划。论文追问：记忆存储必须暴露什么信息，智能体才能在检索之前就知道这一点，并把这种判断单独评分，称为「元记忆监控」。读者只能看到一个不含取值的摘要——按生命周期状态分类的记录计数和一份属性名列表。148 个问题各自针对同一存储的三个版本提问，每个版本只改一个属性，从而排除措辞泄露答案的可能。

Ansuman Mullick, Eray Tüzün

自我演化 LLM 系统何时该停下？（When Is Enough Enough in Self-Evolving LLM Systems?）arXiv 2610.04756v1

自我演化的 LLM 系统会反复提出、评估并采纳针对提示词、技能等持久产物的更新。尽管效果越来越好，这类系统通常在预设的迭代次数或算力预算下运行，缺少一个有原则的判据来判断「继续演化已不再值得」。这会带来两个不良后果：性能饱和之后仍在做无谓计算，以及后期更新过拟合甚至利用评估信号。论文由此提出并研究两个基本问题，试图为自演化过程建立停止准则。

Enoch Yin, Bin Liu, Zhengling Qi

每个 key 值更多价值：面向更快 LLM 解码的非对称稀疏注意力（More Value per Key: Asymmetric Sparse Attention for Faster LLM Decoding）arXiv 2610.04753v2

自回归生成的瓶颈在于注意力的显存与计算开销。稀疏注意力通过只选取注意力矩阵中高概率的条目来缓解，论文观察到一个可利用的结构：在这类方法中，probability-value 相乘的代价变得可以忽略，瓶颈转移到 query-key 一步。因此可以削减 key 头来加速推理，同时保留更多 value 头以维持模型容量，而额外解码开销有限。基于此提出稀疏非对称分组查询注意力 SAGA。

Noam Elata, Itay Lamprecht, Mikey Shechter, Daniel Ohayon 等

APEX：把 LLM 智能体的防护收敛到执行边界（APEX: Active Protection at Execution Boundaries for LLM Agents）arXiv 2610.06966v2

间接提示注入把对抗性指令藏在 LLM 智能体运行时读取的内容里。随着智能体开始组合工具、MCP 服务器与 Skill 等异构能力单元，注入的载体成倍增加，而按攻击模式逐条识别的防御总是落后一步。论文把防御从「覆盖攻击模式」转移到唯一稳定的点上：执行边界——无论载体是什么、注入如何传播，危害都只在智能体把内部状态转化为外部动作或对外输出的那一刻才成为现实。安全判定因此落在这一时刻的检查之上。

MASBench：在部分可观测条件下评测基于 LLM 的多智能体协作（MASBench: Benchmarking LLM-based Multi-Agent Collaboration under Partial Observability）arXiv 2610.04672v1

基于 LLM 的多智能体系统把多个智能体组织成协同团队，去完成单个智能体无法胜任的复杂任务；这种系统的成效不只取决于智能体本身，也取决于协作机制如何设计与组织。论文指出真实世界中的协作通常是部分可观测的——受物理或隐私约束，每个智能体只能访问环境的部分信息。MASBench 正是针对这一条件构建的评测基准，用来检验协作机制在信息不完整时是否仍然有效。
